# journal

- 2026-11-16: discovery changed from ARP requests (spec) to mDNS browsing + TCP port sweep + system reverse lookup, because ARP needs raw socket privileges. specifications.md still mentions ARP, pending architect update.
- 2026-11-16: chose tokio + russh over threads + ssh2 (shared multiplexed sftp session, uniform cancellation, no libssh2/openssl C build). to check: rust toolchain version in the Sailfish SDK vs tokio/russh MSRV; fallback is threads + ssh2.
- 2026-11-17: Sailfish SDK 3.13.5 installed in `~/jolla/sdk` (sfdk at `~/jolla/sdk/bin/sfdk`), VirtualBox build engine, targets SailfishOS-5.1.0.11 for i486, aarch64, armv7hl, emulator "Sailfish OS Emulator 5.1.0.11".
- 2026-11-17: VirtualBox could not start the build engine: first AMD-V disabled in the BIOS, then held by the kvm module on kernel 6.12 (`VERR_SVM_IN_USE`). workaround: `sudo modprobe -r kvm_amd kvm` (or blacklist kvm_amd / boot with `kvm.enable_virt_at_load=0`).
- 2026-11-17: i486 target provides rust/cargo 1.75.0, Qt 5.6.3, sailfishapp 1.2.17, gcc 13.4, `qmltestrunner` (QtTest for QML). crates must be pinned to versions building with rust 1.75, and `Cargo.lock` generated by the target's cargo (the host cargo 1.99 writes a newer lock format).
- 2026-11-17: tokio is limited to 1.53.x by rust 1.75 (1.54 needs rust 1.85). versions are selected by cargo's rust-version aware resolver, run on the host.
- 2026-11-17: rustc fails with "failed to create encoded metadata from file: No such device" when the cargo target dir is in the project: the VirtualBox build engine shares the project through a fuse filesystem without mmap. workaround: `CARGO_TARGET_DIR` on the engine's own disk (`/home/mersdk/cargo-target/sailtree`), set by the spec when the build dir is on fuse/vboxsf. that disk is 8G with about 0.7G free.
- 2026-11-17: the qttypes build script failed with "Failed to execute qmake … Unknown error -1": under scratchbox, spawning the missing `qmake6` it probes first returns a bogus error instead of "not found". workaround: `QMAKE=/usr/bin/qmake`.
- 2026-11-17: `rust`, `cargo`, `rust-std-static` are not preinstalled in the target; `sfdk build-requires pull` installs them from the spec's BuildRequires.
- 2026-11-18: cargo froze for hours (0% cpu, child processes stuck between fork and exec) during a parallel build under scratchbox. workaround, same as Whisperfish: `SB2_RUST_EXECVP_SHIM`, `SB2_RUST_USE_REAL_EXECVP`, `SB2_RUST_USE_REAL_FN`, `SB2_RUST_NO_SPAWNVP` and a single cargo job. a frozen cargo keeps the build directory lock: kill it in the engine before rebuilding.
- 2026-11-18: skeleton rpm builds (about 3 min for a release build from scratch), installs and starts in the emulator through the SailfishApp C++ shim; Silica page renders. qmetaobject 0.2.10 works with Qt 5.6.3.
- 2026-11-18: emulator screenshots: `VBoxManage screenshotpng` gives a garbled image; the lipstick dbus `saveScreenshot` call works once `defaultuser` is in the `privileged` group and the call runs under `sg privileged` (done by `scripts/emulator-run.sh`, emulator only).
- 2026-11-18: the spec's `License` tag is a placeholder (`LicenseRef-TBD`), to be chosen by the architect.
- 2026-11-18: `qmltestrunner` needs `qt5-qtdeclarative-devel-tools` (added to BuildRequires) and only starts with the `minimal` Qt platform in the build target (`offscreen` aborts). Silica components load there, so dialogs can be unit tested.
- 2026-11-18: interface checked in the emulator through screenshots. simulated touches (raw events written to the VirtualBox pointer device) did not land where expected, so interactive states were reached with a temporary copy of the main page driven by a timer, installed in the emulator only. taps, long press menu, remorse countdown and opening a file are not verified by hand yet.
- 2026-11-18: toggling hidden files resets the model, which scrolls the list back to the top.
- 2026-11-18: specifications changed: devices get a current folder shown as a clickable path and their tree starts from it; creation moved from the top bar `+` to an action on the single selected item; sort by name, date, size; adding a device moved to a pull-down. consequences: the "expand down to home on first expansion" logic and the long press menu (new folder, new file, refresh) are removed, devices become selectable, refresh is done by collapsing and expanding or by clicking the last level of the path.
- 2026-11-18: `sfdk deploy --sdk` stayed blocked on "Please confirm installation on device": an install dialog (`sailfish-installationhandler`) was waiting on the emulator screen. `scripts/emulator-run.sh` now copies the rpm and installs it with `rpm -U --force` as root over ssh (emulator only).
- 2026-11-18: the sort `ComboBox` does not follow the model property when it is changed from elsewhere (Silica sets `currentIndex` itself, which drops a binding). harmless as long as the menu is the only place changing the sort.
- 2026-11-18: viewers installed in the emulator to try opening files: `jolla-gallery` (images) from the default repositories, `sailfish-office` (text and documents) from the Jolla apps repository, which had to be added by hand (`ssu ar jolla-apps https://releases.jolla.com/jolla-apps/5.1.0.11/i486/`, `ssu er apps` alone creates no repository). sample files: `~/hello.txt`, `~/Documents/notes.md`, `~/Pictures/sample.png`, `~/Pictures/sample.jpg`.
- 2026-11-18: files opened from the tree were not found by the viewers: Gallery and Documents run under Sailjail and only see the common user folders, and no per-file grant mechanism was found. workaround chosen by the architect: a temporary hard link in `~/Downloads/.sailtree-open/`, checked in the emulator with a text file of the home folder opened in Documents. limits: hard links need the same filesystem and, with the kernel's hard link protection, a file of the user (`ln /etc/hostname` is refused); those files are still not readable by viewers. a viewer's own delete button only removes the link.
- 2026-11-18: the links for opened files are now also removed when the app exits (checked in the emulator with a normal quit). a killed app (SIGTERM, crash) skips that, which is why the cleanup at start stays.
- 2026-11-18: empty files did not open: the system types a file from its content (`inode/x-empty` for an empty one) and no application handles that type. they are now opened by the application matching their name, plain text by default, through `lca-tool`. Documents refused an empty `sailtree.log` ("Unrecognised file type") but accepts an empty `.txt`, hence the link named `<file name>.txt`. checked in the emulator.
- 2026-11-18: size ring: the specification says "ratio of size in current folder"; implemented as the share of the folder the item is directly in, so that every level of the tree reads the same way. to confirm with the architect. Silica's `ProgressCircleBase` draws it.
- 2026-11-18: copy and move: the destination is chosen after the action, with the items kept aside in the model rather than in the selection, because browsing to the destination (collapsing, changing the current folder) unselects what stops being displayed. the theme has no copy icon: clipboard was used for copy, `icon-m-redirect` for move (replaced the same day by the app's own icons).
- 2026-11-18: repeated test launches left many `sailfish-office` processes in the emulator ("Could not register org.sailfishos.Office D-Bus service"); they were killed. only one instance can own the service, a second launch while one runs is handed over to it.
- 2026-11-18: size ring changed after the architect's answer: the ratio is over the direct content of the containing folder. the first version counted the content of every subfolder in the background, which delayed all the rings of a folder; that count is removed, folders have no ring and no size in the details anymore.
- 2026-11-18: own svg icons for copy, move, add, enter and sort; the sort choice moved from the menu to its own button. in a `BackgroundItem`, `parent` of a child is an internal item, not the `BackgroundItem`: its properties must be reached through an id. the build target has no svg image plugin, so the QML tests print "Unsupported image format" warnings for these icons; the emulator has it and the rpm now requires it.
- 2026-11-19: transfers rewritten as jobs working by pieces over the `Fs` operations (progress, cancellation, conflict dialog, queue), replacing the blocking copy of the local backend. settings and the local current folder are saved in `~/.config/sailtree/config.ini`, in a hand written ini format to avoid new crates. file icons by extension.
- 2026-11-19: Silica refuses `pageStack.push` during a page transition and returns nothing; the conflict dialog completes the running transition first and skips the item if the push still fails, so a transfer never waits on a dialog that is not shown.
- 2026-11-19: decision change, to confirm with the architect: ssh goes through the `ssh2` crate (libssh2) instead of `russh`. russh resolves to 0.54 with about 200 crates (aws-lc or ring); the build engine of the SDK has 0.5 GB of disk and 1 GB of memory left, which cannot build that, and its shared folders either lack mmap (fuse) or cannot execute build scripts (vboxsf). ssh2 is the fallback noted on 2026-11-16: 15 more crates, 1.5 minute build. libssh2 is not in the Sailfish repositories, so the copy bundled in `libssh2-sys` is compiled with the app; only openssl and zlib are needed at build and run time. cost: blocking calls, one operation at a time per session. it stays behind `fs/sftp.rs`, so going to russh later only touches that file.
- 2026-11-19: unit tests must not start processes: the launcher lookup for empty files froze a test run under scratchbox (same fork/exec freeze as cargo). the lookup answers "no application" in tests.
- 2026-11-19: sftp tested in the emulator against a second sshd started by hand on port 2200 (`/tmp/sshd_test_config`: password login, no PAM, internal-sftp) with a `sailtest` user (password `sailpw`), because the emulator's own sshd only accepts keys, and with its default configuration the sftp subsystem never answered for that user. checked: key prompt, refused login asking again, listing with links, copy both ways (identical bytes), opening a remote text file. the fingerprint shown matches the one printed by `ssh -v`.
- 2026-11-19: discovery implemented with `mdns-sd` 0.22 and `if-addrs` (12 more crates) plus a threaded connect sweep and `getnameinfo` through libc instead of the `dns-lookup` crate. in the emulator it lists `_gateway` (the host machine, 10.0.2.2) and `SailfishSDK` (the build engine, 10.220.220.254), both found by the sweep and named by reverse lookup. mDNS announcements could not be checked there: nothing announces ssh on those networks.
- 2026-11-19: not done yet for remote devices: key based ssh login; resuming interrupted transfers; FTP over TLS.
- 2026-11-19: left in the emulator for further tries: user `sailtest` (password `sailpw`, member of `sailfish-system`), the test sshd on port 2200 (gone at the next emulator restart; restart it with `/usr/sbin/sshd -D -e -f /tmp/sshd_test_config &` as root), a key pair `/root/.ssh/id_test`, and the remembered device "Test server" (127.0.0.1:2200).
